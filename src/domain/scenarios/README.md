# Scenarios (CF-012)

`composePropertyScenario` is a pure, framework-free entry point for one **already JSON-Schema-validated** `schemas/scenario.schema.json` payload. Parsing, JSON Schema validation, version migration and UI state belong at the application boundary. The `PropertyScenario` TypeScript discriminated union mirrors the saved payload and does not replace runtime JSON Schema validation.

The order is acquisition → selected-down-payment financing → initial-repayment-rate contractual payment → one amortization schedule with eligible recurring/one-time Sondertilgung → fixed-period result → refinancing stress scenarios → exactly one mode-specific result (rent-versus-buy or rental investment) → optional offer-price analysis. The orchestrator calls the public domain APIs and never implements mortgage or acquisition formulas itself. No global state, translation, browser APIs or network calls are used. Input and source metadata remain unchanged; calculated acquisition rates are reported by CF-002. A user-overridden transfer-tax rate is passed through deliberately; the state lookup remains the default when calculating acquisition costs directly.

`PropertyScenarioResult` always contains the full stage results, even when one is unavailable. `status: 'incomplete'` and `unavailableStages` are navigation aids, **not substitutes** for each stage’s typed reason. Underfunded CF-003 results count as incomplete; `not-applicable` refinancing for cash purchases or already repaid loans and `not-requested` optional offer results do not. If a monthly payment is unavailable, zero is passed only as a transport placeholder to CF-008, which first returns its typed `FIXED_PERIOD_UNAVAILABLE` result; zero must never be displayed as an actual contractual payment.

Schema `fullRepaymentTermMonths` selects CF-008’s selected-term refinancing mode; otherwise its explicit `initialRepaymentRate` selects initial-repayment-rate mode. The schema requires `initialRepaymentRate` even in selected-term mode, but it is not used there. Mixed comparison modes or other assumptions are rejected by CF-008 and preserved in the result. The refinancing balance comes only from CF-007, after the last fixed-period payment and Sondertilgung.

Offer analysis is optional. When €/m² bounds and the property’s area are given, the scenario’s explicitly entered purchase price is its comparison offer; the asking price comes from `offerAnalysis`. The schema does **not** provide a maximum monthly affordability payment or an explicitly chosen reference price for an opening-offer range: those subresults remain `not-requested`, even when discounts are stored. Rental yield ceilings use the existing CF-010 result; unavailable metrics remain typed rather than being silently omitted. The CF-009 projection-label correction tracked in issue #29 is separate: do not render that label in a user-facing comparison until the fix is merged.

Tests compose both PD-010 demos and validate exact money results, Sondertilgung, unavailable cascades, underfunding, cash purchase and refinancing assumption mismatch. Future multi-scenario comparison can call this function independently for up to three validated inputs; it should not alter an individual result.
